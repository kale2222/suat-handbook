# SUAT 校园助手设计规格

- 日期：2026-07-15
- 状态：已确认，待实现计划
- 适用项目：SUAT 手册（Docusaurus 3.10）

## 1. 背景与第一性原理

校园助手的目标不是“在网站里放一个 AI 聊天框”，而是让学生用自然语言，更快、更可靠地找到 SUAT 手册中已有的信息。

第一版把可信检索作为独立、完整的产品能力。大模型只作为未来可选的表达层：它可以把已经命中的可靠资料整理成简短回答，但不能决定事实、编造来源或替代原文。

## 2. 目标与非目标

### 2.1 目标

1. 学生可以从网站任意页面打开校园助手并用自然语言提问。
2. 助手只依据仓库内明确收录的 Markdown 和 PDF 回答。
3. 每个结果都能追溯到文章章节或 PDF 页码。
4. 找不到可靠依据时明确拒答，并引导用户查看相关页面或提交内容建议。
5. 没有账号、数据库、API Key 和大模型时，第一版仍然完整可用。
6. 未来接入任意模型供应商时，不重写聊天界面和知识索引。

### 2.2 非目标

第一版不实现：

- 学号、统一身份认证或其他登录能力；
- 向量数据库、Embedding 和网络搜索；
- 多轮语义对话、跨设备历史和云端会话保存；
- 语音、文件上传、模型选择和人工客服；
- Word、PPT 等额外知识源格式；
- 问答统计后台和 AI 回答缓存。

## 3. 产品形态与交互

### 3.1 入口

- 全站右下角固定一个品牌紫色的“校园助手”悬浮按钮。
- 桌面端点击后打开约 380 × 560 px 的右下角面板。
- 移动端打开接近全屏的面板，输入区需避开软键盘和安全区域。
- 用户可以通过关闭按钮、遮罩或 `Esc` 关闭面板。

### 3.2 初始状态

面板标题为“SUAT 校园助手”，副标题为“资料检索版 · 仅依据 SUAT 手册”。初始页展示：

- 一句能力说明；
- 三个示例问题；
- 最多 200 个字符的输入框；
- “内容由学生共建，重要信息请以原文为准”的提示。

### 3.3 结果状态

本地检索版展示：

1. 命中文章与章节标题；
2. 与问题相关的原文摘要；
3. 文章链接或 PDF 页码；
4. 来源类型与核验日期（若已记录）。

未来 AI 版在相同位置增加“直接结论 + 最多三个步骤”，来源区域保持不变。回答以简洁为风格目标，不用固定汉字数截断关键信息；服务端通过最大输出 token 控制成本。

### 3.4 会话行为

- 同一时间只处理一个问题。
- 第一版每个问题独立检索，不依赖上一轮语义。
- 会话只保存在页面内存中：站内路由切换时保留，完整刷新或关闭网站后清空。
- 点击来源进入对应内容，返回后仍可查看当前会话。

## 4. 知识来源与元数据

### 4.1 Markdown

默认收录 `docs/**/*.md`。索引保存文章标题、章节标题、分类、正文、页面路径、贡献者和可用的核验日期。

文章可通过 frontmatter 增加：

- `assistant_keywords`：学生口语、简称和同义表达；
- `assistant_exclude`：设为 `true` 时明确排除该文章；
- `source_type`：`student` 或 `official`，默认 `student`；
- `last_verified`：内容最后人工核验日期。未填写时显示“未标注核验日期”，且检索排序不获得新鲜度加成。

### 4.2 PDF

不自动扫描并收录 `static/` 下的所有 PDF。额外 PDF 必须在 `assistant/sources.json` 中明确登记，避免无关、重复、过期或内部文件被意外索引。

每个 PDF 条目必须包含：

- 稳定 ID；
- 文件路径与展示标题；
- `source_type`；
- `last_verified`；
- 排序优先级。

PDF 按页提取文字并保留页码。无法提取文字的扫描版 PDF 在构建时产生明确警告并排除，不静默生成空内容。

### 4.3 内容安全边界

所有知识源必须已经适合公开展示。私人文件、学号名单、内部材料和其他敏感信息不得进入知识清单或生成索引。

发生内容冲突时，先比较相关性，再比较核验日期和来源类型；助手不隐瞒冲突，应同时展示冲突来源并提醒用户查看最新官方通知。

## 5. 索引生成与中文检索

### 5.1 构建时处理

网站构建前执行知识索引脚本：

1. 解析 Markdown frontmatter、标题和正文；
2. 解析清单内 PDF 的文本与页码；
3. 按标题层级和段落切分，超长章节继续拆分；
4. 为每个片段附加来源元数据；
5. 输出版本化的静态知识索引。

生成文件只包含公开资料，并在用户第一次打开助手时懒加载，不能进入首页关键加载路径。

### 5.2 检索策略

第一版使用适合中文的小型本地检索方案：

- 标题、章节名和 `assistant_keywords` 权重最高；
- 正文使用中文字符片段和关键词匹配；
- `assistant/synonyms.json` 维护有限的校园同义词，例如“卡掉了 → 校园卡丢失、补办”；
- 当前文章只在结果分数相近时作为并列排序因素，不能覆盖明显更相关的其他文章；
- 最多返回三个主要结果。

置信度阈值由离线评测集校准。低于阈值时显示“手册暂未收录”，不能用低相关内容拼成答案。

## 6. 组件边界与数据流

前端定义统一的问答接口：

```text
ask(question, currentPath) → result
```

`result` 是以下明确状态之一：

- `sources`：可靠的本地检索结果；
- `answer`：未来 AI 生成的有来源回答；
- `not_found`：没有可靠依据；
- `error`：索引或服务暂时不可用。

第一版由本地检索实现该接口。未来远程实现只替换接口内部逻辑，悬浮按钮、聊天面板和结果卡片保持不变。

第一版数据流：

```text
Markdown / PDF → 构建脚本 → 静态知识索引
用户问题 → 归一化与同义词扩展 → 本地检索 → 来源结果或明确拒答
```

未来 AI 数据流：

```text
用户问题 → 自有服务端接口 → 服务端检索 → 模型整理 → 答案 + 来源 ID
```

## 7. 未来 AI 接入约束

模型供应商选择与 API 接入不属于第一阶段范围，只在第三阶段启动时决定。接入时必须遵守：

1. 浏览器只请求项目自己的服务端接口，不能直接调用模型供应商。
2. 服务端重新检索知识索引，只向模型发送最相关的少量片段。
3. 模型只能依据提供的片段回答，不能网络搜索或自由补充。
4. 来源 URL 由项目根据来源 ID 生成，不能采用模型输出的链接。
5. 免费额度耗尽、请求超时、响应格式错误或来源缺失时，自动退回本地检索。
6. 缓存只在真实 AI 流量证明有需要后增加，第一版不提前实现。

## 8. API Key 与隐私

未来 API Key 的硬性安全规则：

- 生产 Key 只保存在托管平台的服务端环境变量中；
- 本地 Key 只放在已被 Git 忽略的 `.env.local`；
- 仓库只允许提交不含值的 `.env.example`；
- `src/`、`static/`、`docusaurus.config.ts`、生成索引和客户端构建产物中禁止出现 Key；
- 接入 API 时增加密钥扫描；发现泄漏后立即吊销并轮换，不能只删除 Git 文件。

第一版不记录原始问题、IP 或会话。未来限流如需短期处理 IP，应使用不可逆摘要并设置自动过期，不能建立学生行为档案。

## 9. 错误处理与降级

- 索引尚未加载：展示明确加载状态，禁止重复提交。
- 索引加载失败：展示重试按钮和网站普通搜索入口。
- 没有可靠匹配：展示“手册暂未收录”、相关页面和投稿入口。
- AI 请求超过 10 秒：取消等待并展示本地检索结果。
- AI 配额耗尽、服务错误、格式错误或缺少来源：丢弃 AI 输出并展示本地结果。
- 内容更新：索引版本变化后清除对应旧缓存，避免返回过期回答。

医疗、心理、安全和校规等重要信息必须突出来源与核验日期。紧急问题只展示仓库已有的官方联系方式，不能由模型编造电话或处理流程。

## 10. 内容反馈闭环

当助手无法找到答案时，提供“提交这个问题”入口，链接到项目已有的建议收集表，同时提供最接近的手册页面。

反馈入口用于发现内容缺口，而不是收集聊天历史。维护者可以把高频缺口转化为新文章、`assistant_keywords` 或同义词条目，使助手和手册内容一起改进。

## 11. 测试与验收

### 11.1 离线检索评测

在 `assistant/eval-cases.json` 中维护至少 30 个真实学生表达，覆盖：

- 四个主要内容分类；
- 口语、简称、同义词和常见错别字；
- 跨章节问题；
- 手册未覆盖的问题；
- 与学校无关的问题。

验收指标：

- 有答案的问题中，至少 90% 的预期文章进入前三个结果；
- 明确无关或无资料的问题不得生成手册答案；
- 所有来源链接和 PDF 页码可解析；
- 内容或同义词更新后自动重跑同一评测集。

### 11.2 功能与质量

- 全站可以打开、关闭并操作校园助手；
- 桌面、移动端、深色模式和软键盘场景正常；
- 键盘可操作，支持 `Esc`、焦点管理和无障碍标签；
- 输入安全渲染，不能注入 HTML；
- 知识索引只在首次打开助手时加载；
- `npm run build` 与 `npm run typecheck` 通过；
- 没有 API Key 时，本地检索仍完整可用；
- 第一阶段模拟索引加载失败，确认重试与普通搜索入口可用；
- 第三阶段接入 AI 时，再增加超时、配额耗尽和错误响应的降级测试。

## 12. 分阶段交付

### 第一阶段：资料检索版

- 悬浮按钮和响应式面板；
- Markdown 与显式 PDF 来源清单；
- 中文本地检索、同义词和来源卡片；
- 明确拒答、投稿入口和离线评测。

### 第二阶段：根据真实反馈改进检索

- 从同学实际表达中扩充评测集、关键词和同义词；
- 为时效性内容补充 `last_verified`；
- 根据误命中调整置信度和排序权重。

### 第三阶段：可选 AI 表达层

- 选择可访问、成本可控的模型供应商；
- 增加服务端接口、密钥保护、限流和硬预算；
- 保留本地检索作为永久降级路径。

第一版的成功标准不是“模型能聊天”，而是学生不用翻目录，也能通过自然语言在前三个结果中找到正确、可验证的手册内容。
